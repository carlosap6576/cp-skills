# gstack Expert Roster — post-implementation tier

Reference for `/code-execute`'s Step 4 (execution-time awareness) and Step 6
(advisory and `--skill` chaining).
Verified against gstack 1.99.1.0 by hand. The **live, machine-verified
snapshot** is `$SKILL_DIR/prompts/gstack-contract.md`, regenerated by the
cp-skills installer whenever gstack is installed or upgraded: every invokable
gstack expert with its description and chain-safety scan, the retired and
not-invokable skills, and `/review`'s specialists, flags and thresholds.
**Read it first; where it disagrees with this file, it wins.** The tables
below are worked examples, not a whitelist: choose the invokable expert that
best suits what the work actually touched, including one gstack added after
this file was written, and say in one line why it fits.

**This file is enrichment, never a dependency.** No gstack installed →
the
`/code-validation` recommendation stands alone; never block or warn beyond one line.

## The roster

| Skill | What it is | Reach for it when |
|---|---|---|
| `/code-validation` | Sibling skill: audits the implementation against the plan, fixes and refactors it, tears down proof-only scaffolding, proves it green, deletes the plan | **Always the next step** after execution |
| `/verify` | Runs the repo's declared checks plus the tests the pre-ship gate would pick, fixes what breaks, repeats until green; no review, no git | A fast green loop is wanted on the working tree |
| `/qa-only` | Report-only QA of a browser, API, CLI, job, worker or webhook surface | The plan built observable behavior and findings are wanted without another skill editing code |
| `/cso` | Evidence-first security audit: a finding needs an attacker-controlled entrypoint, a crossed boundary, demonstrated impact and challenged controls | Execution touched auth, secrets, user input, uploads, subprocess, webhooks, LLM/agent tooling, CI/CD, or network-facing code |
| `/review` | Pre-landing diff review with specialist subagents and an adversarial pass; fix-first | The validated change is about to land, on a feature branch |
| `/design-review` | Designer's-eye QA on the rendered page; `--build <preview url>` checks UI during the build without committing | Execution touched UI components, pages, or styling |
| `/devex-review` | Live developer-experience audit: time-to-hello-world, error-message quality, docs findability | Execution built CLIs, tooling, SDKs, scripts, or install flows |

| `/test-audit` · `/deslop-shared-libs` | Find low-value or duplicate tests · find worthwhile shared-code extractions; both read-only | The suite or the codebase grew repetition around the change |
| `/health` | Read-only quality dashboard over the repo's own typecheck, lint, test and dead-code tools | A quality snapshot of the touched area is wanted |
| `/qa` · `/document-release` · `/ship` · `/land-and-deploy` · `/canary` | Fixing QA, docs sync, landing, deploy, post-deploy watch — all human-run | The person landing the change wants them |
| `/codex` | Outside-model second opinion (`review`, `challenge`); never modifies files | A cross-model read is wanted before landing |

**Retired in gstack 1.98 — never name them:** the standalone root-cause

## Chain safety — what the pipeline may invoke by itself

The pipeline runs unattended and never writes git, so an expert is chained
only when it neither waits for a person nor commits, pushes, merges, stashes
or rebases. The snapshot's "Chain safety scan" column is the mechanical check
on the installed version; when it flags a skill as a git writer, that wins
over this table.

| Tier | Skills | Rule |
|---|---|---|
| Chain-safe | `/verify`, `/qa-only`, `/cso`, `/deslop-shared-libs`, `/test-audit`, `/health`, `/design-review` with `--build` | May be chained by `--skill`. No git writes; no question when the target is unambiguous and the session kind is `spawned` |
| Explicit-only | `/review` | Chained only when the user named it. It runs `git fetch origin <base>`, edits source (AUTO-FIX), may post PR replies when a PR exists, and exits with "Nothing to review" when the checkout is on the base branch |
| Human-run | `/qa`, `/design-review` (default mode), `/document-release`, `/document-generate`, `/ship`, `/land-and-deploy`, `/canary`, `/modernize`, `/ios-fix`, `/ios-sync`, `/spec`, `/write-skill`, `/retro` | Never chained. They commit, push, merge, deploy, restore, or need a person at a gate. Print `run yourself: /<skill> — <why>` |

How unattended gstack runs resolve their own questions: the session kind is
read only from the `gstack-skill-start` preamble (`SESSION_KIND:` echo), never
from prompt text. `GSTACK_SESSION_KIND=spawned` prefixed on that command makes
a skill take its recommended option and never a destructive one;
`unattended` leaves consents and approval gates pending; `headless`
(`GSTACK_HEADLESS`, `CI`) makes a question BLOCK, so never rely on it. There
is no `--yes`/`--auto` flag on any gstack skill.

Expert-specific prerequisites:
- `/verify` asks once for consent to run repo commands unless its runner gets
  `--allow-repo-commands`; it stops after 5 runs or when the same failure
  returns twice, and never weakens a test or checker config to get green.
- `/cso` needs its compiled launcher; its scanners run in Docker and degrade
  to a static audit without it. Scopes are mutually exclusive: `--code`,
  `--infra`, `--skills`, `--supply-chain`, `--owasp`, `--scope <domain>`;
  modifiers `--diff`, `--base <ref>`, `--offline`, `--paths <p,q>`;
  `--comprehensive` adds reproduction and repair candidates.
- `/qa-only` covers browser, API, CLI, job, worker and webhook surfaces
  (`--quick`, `--regression <baseline>`); it never commits and works on a
  dirty tree. `/qa` is the fixing twin: it requires a clean tree and commits
  each fix.
- `/design-review --build <preview url>` runs on loopback only, never commits,
  stashes or asks, and stops editing after three rounds; the default mode
  requires a clean tree and commits each fix.
- `/health` asks nothing only when CLAUDE.md has a `## Health Stack` section.
- `/test-audit` is report-only when spawned; `/deslop-shared-libs` never
  writes anything.

## `/review` mechanics (verified 1.99.1.0)

`/review` diffs the working tree and untracked source against
`git merge-base origin/<base> HEAD`, so uncommitted work is covered, but only
on a feature branch. It never commits, pushes or opens a PR. Knowing its
dispatch rules lets the advisory name the flags that guarantee coverage:

- **Core pass on every diff**: SQL and data safety, races and concurrency, LLM
  output trust boundary, shell injection, enum and value completeness, gate
  integrity (a removed test, a suppression pragma, a relaxed gate value, a
  swallowed exception are always ASK findings), plus the shared-code check,
  an exploratory QA smoke, and the adversarial pass.
- **Always dispatched at 50+ changed lines**: `testing` and `maintainability`.
- **Under 50 lines every specialist is skipped except `state-machines`.** A
  small but risky change needs a force flag to get specialist eyes.
- **Scope-gated**: `security` (auth scope, or backend scope and more than 100
  lines), `performance` (backend or frontend scope), `data-migration`
  (migration files), `api-contract` (API scope), `design` (frontend scope,
  checklist-driven), `simplification` (more than 100 lines; advisory only,
  tags `delete` / `stdlib` / `native` / `speculative` / `shrink`, never cuts
  tests, error paths, validation, security or accessibility),
  `state-machines` (state-machine scope true or unknown).
- **`red-team`** activates past 200 lines or after any CRITICAL finding. No
  flag summons it.
- **`targeted`** (money, gate, auth and secret code: a paid call without a
  cap, a check that fails open, a verdict bound to the wrong commit, a secret
  written to logs or child args) is dispatched by `/ship`'s review plan, not
  by a force flag.
- **Adaptive gating**: a conditional specialist with 0 findings in 10+
  dispatches is skipped, except `security` and `data-migration`
  (`[NEVER_GATE]`).
- **Force flags** (in `args`): `--security`, `--performance`, `--testing`,
  `--maintainability`, `--data-migration`, `--api-contract`, `--design`,
  `--simplification`, `--state-machines`, `--all-specialists`.
- **Depth follows risk, not size** (light / standard / full); at most 2 review
  rounds and 3 fix cycles.
- **Fix-first**: dead code, N+1, stale comments, magic numbers and missing LLM
  output validation are edited in directly; security, races, design
  decisions, fixes over 20 lines, removed functionality and every gate
  finding are ASK items (left open when spawned).
- **Freshness binds to content**: the tree is captured before and after; an
  edit during the pass, or a fix-range re-review, never counts as CURRENT.
  Keep the tree frozen while reviewers run.
- **Shared-code check on every diff**: needs 2+ verified first-party callers,
  reuses existing helpers first, and emits extractions as `[ADVISORY]` rows
  that are ASK-only and never lower the score. Maintainability reports only
  duplicated behavior that already produces a wrong result.
- **Plan-completion audit**: every actionable plan item is DONE / PARTIAL /
  NOT DONE / CHANGED / UNVERIFIABLE; name the plan path in `args`.
- **Claims need citations**: "safe" cites the line, "tests cover this" names
  the test. Findings under confidence 5 drop to an appendix.

Used by Step 6's advisory (at most TWO rows; the `/code-validation` line

|---|---|

| UI components, pages, styling | `/design-review --build <preview url>`; `/qa-only` when the flow is walkable |

| CLI, tooling, scripts, install/setup, SDKs | `/devex-review` |
| DB schema, migrations, backfills | `/review --data-migration` (add `--performance` for indexes or large tables) |
| Public API surface, webhooks, response shapes | `/review --api-contract` |
| State machines, status enums, workflow transitions | `/review --state-machines` |
| A refactor, new abstraction, or new dependency | `/review --simplification --maintainability` |
| The same logic now lives in several places | `/deslop-shared-libs` |
| Many new tests, or tests that only exercise test-only seams | `/test-audit` |

| A check that stays red for an unexplained reason | No skill: hand it to `/code-validation` with the verbatim failure |

## Execution-time awareness (facts that change how Step 4 behaves)

- **Verification evidence binds to tree content.** A "tests pass" claim is
  citable only for the exact tree it ran on. `/code-validation` edits the tree
  after you, so only its final pass counts: do not spend the run on full
  verification.
- **The repo may declare its verify command** (`<!-- gstack:verify: <cmd> -->`
  in CLAUDE.md). Use the same toolchain for self-checks; leave the full
  command to the validator. An armed `gstack-verify-gate` Stop hook: run the
  command once, fix what your edits broke, hand off the rest.
- **Guardrails fail closed.** `/freeze` and `/guard` deny edits outside their
  boundary, and the boundary persists across sessions; `/careful` denies
  destructive commands. A denied call is a decision to report, never to work
  around.
- **Claimed limitations need evidence.** "Unreachable" or "the API can't" is
  stated only with the probe's verbatim failure next to the `[MOCKED]` flag.
- **Over-built code will be flagged.** The simplification rubric names
  one-implementation abstractions, hand-rolled stdlib, dependencies
  duplicating platform features and dead flexibility; the reuse ladder exists
  so there is nothing to find. Coverage up, unrequested structure down.
- **Removing or loosening a gate is a finding by itself**: a deleted test, a
  suppression pragma, a relaxed threshold, a swallowed exception. Never do it
  to get a step through.
- **Accepted shortcuts leave a trail.** Carry a `gstack-shortcut(dec-<id>)`
  marker only when the plan's Decisions to record names it; never invent one.
- **UI is calibrated against `DESIGN.md`.** Use its tokens, type scale,
  spacing and motion rules verbatim.
- **Extraction advice is not a defect.** Do not perform a broad shared-code
  extraction the plan did not ask for; divergent copies that already produce
  a wrong result are defects.
- **Secrets never reach gstack's memory.** Its learnings and timeline writers
  refuse secret-shaped text; this skill writes neither.
